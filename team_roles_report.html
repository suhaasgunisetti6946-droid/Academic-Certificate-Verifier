CertiChain: Blockchain Certificate Verifier

3rd-Year B.Tech Mini Project — Team Contribution & Individual Roles
Academic Year: 2026
Department: Computer Science & Engineering
Team Size: 5 Members
Project Overview: CertiChain is an end-to-end decentralized application (dApp) developed to eliminate academic credential fraud. It securely hashes certificates client-side using SHA-256 and records the immutable proof on the Ethereum Sepolia Testnet. Below is the simplified breakdown of the five distinct roles and individual contributions made by each team member.
Member 1: Team Lead & Smart Contract Engineer Backend / Blockchain
Focus: Solidity Contract Design, Access Control & Sepolia Deployment
What They Have Done (Simple Context):
  • Authored the Smart Contract: Wrote CertificateVerifier.sol in Solidity (^0.8.20), setting up the core data structure to map a 32-byte document hash to student details.
  • Role-Based Access Control: Created the onlyAdmin security modifier ensuring that only the authorized university/institution wallet can issue or revoke credentials.
  • Gas & Data Optimization: Kept gas costs low by storing only the 32-byte SHA-256 hash rather than the full PDF file on the Ethereum blockchain.
  • Testnet Deployment: Deployed the smart contract onto the Ethereum Sepolia Testnet using Remix IDE and verified its contract address.
Viva Defense Question: "Why do we store only the document hash on-chain rather than the entire PDF?"
Answer: Storing large files on Ethereum is prohibitively expensive in gas fees and exposes private student data. Hashing maps any file size to exactly 32 bytes, guaranteeing zero data leakage while ensuring mathematical tamper-evidence.
Member 2: Frontend & UI/UX Design Specialist UI/UX / Styling
Focus: Glassmorphism Interface, Layout Architecture & User Experience
What They Have Done (Simple Context):
  • Dark-Glassmorphism Interface: Designed the sleek dark user interface using deep slate tones (#0f172a), blur backdrops, and glowing emerald/cyan accent states in style.css.
  • Dual-Tab System: Built the seamless tab navigation in index.html separating the Admin Issuance Portal from the Public Verification Portal.
  • Drag-and-Drop Zones: Created interactive file dropzones allowing users to drag and drop PDFs or images effortlessly.
  • Status Visuals: Styled glowing visual feedback cards: an emerald green "Authentic & Verified" badge for valid certificates and a crimson red "Invalid / Tampered" card for fakes.
Viva Defense Question: "How does the interface handle non-technical users and recruiters?"
Answer: The public tab requires no wallet login or cryptocurrency. Anyone can simply drag a student's certificate into the browser to get an instantaneous pass/fail verification result.
Member 3: Web3 & Cryptographic Integration Engineer Web3 / Cryptography
Focus: Client-Side SHA-256 Hashing & MetaMask Ethers.js Connectivity
What They Have Done (Simple Context):
  • Client-Side Hashing: Implemented the browser native Web Crypto API (crypto.subtle.digest("SHA-256")) so certificate files are converted into unique cryptographic digests right inside the user's browser without uploading files to any external server.
  • MetaMask Wallet Integration: Integrated Ethers.js v6 to detect MetaMask, connect user accounts, track chain changes, and enforce the Sepolia network.
  • Smart Contract Interaction: Hooked frontend action buttons to the contract's issueCertificate() transaction and verifyCertificate() read calls.
  • Public RPC Fallback: Configured a fallback JSON-RPC provider so employers can verify certificates on Sepolia even if they don't have MetaMask installed.
Viva Defense Question: "What is the mathematical principle preventing document forgery?"
Answer: The SHA-256 Avalanche Effect. Even modifying a single letter or pixel in the certificate changes roughly 50% of the hash output, producing an immediate mismatch on the blockchain ledger.
Member 4: QA, Testing & Demo Simulation Engineer Testing / Simulation
Focus: "Demo Mode" Engine, Edge-Case Testing & Sample Artifact Generation
What They Have Done (Simple Context):
  • Built "Demo Mode (Without Wallet)": Created the local mock simulation engine in app.js using localStorage, allowing faculty to test the complete issuing and verification workflow without MetaMask or gas fees.
  • One-Click Sample Loader: Added the "Load Sample Certificate" feature so evaluators can populate and test the pipeline with one click during the presentation.
  • Tamper Testing & Edge Cases: Tested various failure modes (modifying certificate text, tampering with hash strings, re-issuing duplicate hashes, unauthorized non-admin wallets).
  • Sample Certificate Generation: Designed sample_certificate.html as a realistic university diploma artifact for live evaluation demonstrations.
Viva Defense Question: "How can the project be demonstrated if the internet or MetaMask fails during the viva?"
Answer: By switching on the built-in 'Demo Mode' toggle, the app runs an entirely offline cryptographic simulation displaying real-time SHA-256 calculation and verification states.
Member 5: DevOps, Deployment & Technical Documentation Lead DevOps / Documentation
Focus: GitHub Pages Deployment, Academic Justification & Project Report
What They Have Done (Simple Context):
  • GitHub Pages Deployment: Configured a zero-build static architecture (CDN-based Ethers.js & FontAwesome) enabling direct deployment on GitHub Pages without requiring complex build tools or npm dependencies.
  • Authored Comprehensive README: Formulated the academic justification section explaining the limitations of traditional centralized databases vs. the decentralized tamper-proof blockchain architecture.
  • Architecture Diagrams: Drafted the end-to-end system sequence diagrams illustrating the university-to-blockchain-to-employer verification flow.
  • Project Report & Viva Preparation: Compiled technical specifications, test reports, and viva question-and-answer briefs for the entire team.
Viva Defense Question: "What makes this project architecture production-ready and cost-effective?"
Answer: It separates the heavy file storage (kept client-side) from the verification logic (32-byte hash on Ethereum). It has zero server maintenance costs because the frontend is hosted statically and the backend runs on decentralized blockchain nodes.
